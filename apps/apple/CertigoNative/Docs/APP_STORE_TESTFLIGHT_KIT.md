## Truth gates before using the copy

The ten pillars describe the product direction, not ten independently verified
production features. The draft copy below deliberately qualifies availability.

| Pillar | What the candidate can describe | Required release proof |
| --- | --- | --- |
| Study Plan | Local target date, starting level and daily minutes | Owner/track scope and deletion on the actual device |
| Six-phase micro-learning | Design target; original editorial pilot is separate | A published six-phase curriculum and a complete real journey; **do not advertise six phases yet** |
| Active practice | Available question packs and server corrections | Actual supported question types; do not promise all eight renderers |
| Completed is not mastered | Separate completion and evidence-based indicators | Do not infer domain mastery from a score alone |
| Spaced repetition | Server recommendations when returned | No invented due dates or offline grades |
| Pedagogical AI Coach | Explanation requested after a confirmed answer | Live response, source labeling, consent/privacy disclosures |
| Personalized guidance | Available learner evidence and recommendations | No invented prediction, calibrated pass probability or guaranteed success |
| Motivation | Returned XP, achievements and quests | Server-confirmed values; no local reward credit for pending answers |
| Focus Area | Available domain scores and mapped recommendations | No invented coverage, mastery or recommendation duration |
| Mock / final assessment | Generate and submit when service supports it | Supported renderer, manifest pin, idempotency; unavailable/empty exams stay unavailable |

“35 global providers” is a catalog ambition, **not evidence of 35 providers with
playable published courses**. Certification-family classification is not a
partnership, endorsement or course-availability guarantee. The public drafts use
“provider families” without an unverified count. Add a count only after checking
the production catalog and exactly what is available in the submitted build.
Do not put third-party company names in keywords.

Interface languages are French, English, Hindi (not every language of India),
simplified Chinese, Korean, Spanish, Italian and German. Source questions,
editorial lessons and server explanations are not automatically translated by
the interface picker. Do not advertise eight translated question banks.

## Localized metadata

`fr` → French, `en` → English (U.S.), `hi` → Hindi, `zh-Hans` → Chinese
(Simplified), `ko` → Korean, `es` → Spanish (Spain), `it` → Italian,
`de` → German. Add regional variants separately only after editorial review.
Fields below are plain text; headings and Markdown fences are not field content.
Keywords are constrained to **100 UTF-8 bytes**, stricter than 100 characters.
Descriptions stay under 4,000 characters. Have native speakers review the drafts
and verify the lengths again in App Store Connect.

## One-command Mac preparation

Reuse the user's single permanent checkout and existing Xcode project. Do not
clone per validation, reset local changes, delete old logs/results or alter
signing. Save/commit deliberate local changes first. The script refuses any dirty
checkout and a branch/upstream other than `main`/`origin/main`.

After this kit is integrated, run from that checkout using an **existing**
Simulator UUID listed by `xcrun simctl list devices available`. First verify an
unused build number and intended version in App Store Connect. Set the two
distribution values to those verified values, not the placeholder strings:

```bash
CERTIGO_SIMULATOR_ID='EXISTING-SIMULATOR-UUID' \
CERTIGO_DISTRIBUTION_VERSION='VERIFIED-MAJOR.MINOR.PATCH' \
CERTIGO_DISTRIBUTION_BUILD='VERIFIED-INCREASING-INTEGER' \
bash tools/validate_apple_mac_one_shot.sh --prepare-archive
```

The script performs `git pull --ff-only`, records the exact tested revision and
Xcode/Swift versions, runs package unit tests, builds the Simulator app, executes
the existing three protection XCTest tests and prepares an **unsigned**
Distribution archive. Logs, xcresult and DerivedData stay in a new unique
directory under `~/Library/Logs/Certigo`, outside the checkout; existing evidence
is not deleted. Every failure stops the command and preserves evidence.

**Known source limitation at the dated base:** the native app scheme has no
testables and there is no native UI-test target. Building it is not running UI
tests. The script reports that gap and exits **3**, even if the other stages
succeed. It can execute a subsequently integrated real shared UI test scheme
when both `CERTIGO_UI_TEST_PROJECT` and `CERTIGO_UI_TEST_SCHEME` are supplied.
It requires an enabled testable and a UI-testing target, then checks for executed
passing tests with zero skips/failures. Inspect the named tests: a green total
does not prove coverage of all journeys. `CertigoProtectionTests` is not a UI
suite, and the Linux-only `test_apple_model.sh` is not run as a macOS test.

The Distribution target has signing disabled in source. The archive is
preparation only, **not an uploadable TestFlight build**. The script neither
enables signing nor uploads, exports an IPA, installs profiles, requests cloud
permissions or changes an App Store record. Validated production CIAM metadata,
existing bundle identity, compatible signing/profile/entitlements and a signed
device-tested archive remain release gates. A version-format check does not
prove App Store Connect accepts that version/build.
